# Dashboard financial calendars

Two optional main Dashboard widgets controlled only by the shared dashboard date range. A single month has no redundant month label or navigation; multi-month ranges use a scrollable sequence of labeled months. Partial periods leave out-of-range days blank; future dates have no recorded activity. Requests are split into month-sized slices and made sequentially. Both use the actual number of calendar weeks, padding the final row only, and stretch week rows into the existing bounded tile. Hovering or keyboard-focusing a date displays a compact shared tooltip with the date, totals, category amounts and percentage of absolute activity within each currency. Clicking any nonfuture date opens the existing Transactions page with that date's start/end filters. Spending selects expenses and excludes transfers/planned rows; the funding calendar passes the exact source transaction IDs that produced its day totals, including transfers; unrelated transactions are not shown. The removable Calendar activity filter also scopes summaries and bulk actions; an empty selection matches no rows. Clearing or changing the date clears that selection. Previously saved filters do not narrow the deep link. No detail dialog or separate daily records query. Existing widget sizes and layouts are preserved.

- **Income & Contributions Calendar** reads actual posted native account transactions, not payroll statements, Google Sheets, principal cash-flow records, balance history or aggregated portfolio funding. Green shows ordinary non-transfer income received into spendable accounts; blue shows outgoing transfers to investment/retirement accounts or explicitly recognized brokerage payments; yellow shows outgoing transfers to savings. Existing owned account categories, explicit Personal Finance account mappings and confirmed transfer rules provide destination metadata only, never amounts. A narrow exact brokerage-name match (M1, Public, Robinhood) can show an otherwise unassigned outgoing payment from a spendable account; the calendar does not assign a native portfolio. A linked transfer counts once on its outgoing date even if the credit posts later. Same-role transfers do not count as new funding. Linked portfolio bank debits count once; standalone portfolio-only funding and unmatched receiving legs are not included to avoid counting unlinked duplicate bank/broker records. Unrecognized destinations remain unclassified. No guesses about trades, market returns or portfolio allocation. Pending, excluded, refunded, planned, balance-adjustment and payment-child records are excluded. Ordinary income is actual received income, not necessarily payroll only; transfers and brokerage/savings income are not counted as pay. Native amounts retain their actual currency. Owner-only reporting mappings are used as classification metadata; native account categories work for other users.
- **Spending Calendar** uses the existing split-aware, refund-netting pivot engine with internal daily buckets and root category colors. Tooltips show net category totals; the Transactions page displays underlying ledger expenses, which can differ from net report totals.

Each day has a dominant-color tint and proportional segmented strip. Funding categories are not additive income. Each request is limited to a month; a padded bank transaction query captures cross-month transfer legs. No provider requests, full investment analytics or Sheets history reads. Read-only; no migration or financial writes. The exact-ID drilldown requires rebuilding both backend and frontend. Verify actual M1 rows and other destinations on the deployed dashboard before claiming coverage.

Both calendar widgets now also support 1×1. Compact tiles reduce padding, day-cell height, and text size, show one total per currency, and preserve hover breakdowns, color bands and date links. Existing default sizes remain unchanged. On unbounded mobile layouts, compact rows retain a usable minimum height.

In desktop edit mode the calendar tile reserves the measured height of its toolbar instead of allowing the toolbar to obscure the last week. Other widgets retain their existing layout.
