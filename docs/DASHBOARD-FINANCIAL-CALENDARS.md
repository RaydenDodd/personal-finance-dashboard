# Dashboard financial calendars

Two optional, independently navigable main Dashboard widgets. Both use the actual number of calendar weeks, padding the final row only, and stretch week rows into the existing bounded tile. Clicking a date opens a scrollable detail dialog rather than expanding the tile. Existing widget sizes and layouts are preserved.

- **Income & Contributions Calendar** reads actual posted native account transactions, not payroll statements, Google Sheets, principal cash-flow records, balance history or aggregated portfolio funding. Green shows ordinary non-transfer income received into spendable accounts; blue shows outgoing transfers to investment/retirement accounts or explicitly recognized brokerage payments; yellow shows outgoing transfers to savings. Existing owned account categories, explicit Personal Finance account mappings and confirmed transfer rules provide destination metadata only, never amounts. A narrow exact brokerage-name match (M1, Public, Robinhood) can show an otherwise unassigned outgoing payment from a spendable account; detail explicitly labels that portfolio assignment unverified. A linked transfer counts once on its outgoing date even if the credit posts later. Same-role transfers do not count as new funding. Linked portfolio bank debits count once; standalone portfolio-only funding and unmatched receiving legs are not included to avoid counting unlinked duplicate bank/broker records. Unrecognized destinations remain unclassified. No guesses about trades, market returns or portfolio allocation. Pending, excluded, refunded, planned, balance-adjustment and payment-child records are excluded. Ordinary income is actual received income, not necessarily payroll only; transfers and brokerage/savings income are not counted as pay. Native amounts retain their actual currency. Owner-only reporting mappings are used as classification metadata; native account categories work for other users.
- **Spending Calendar** uses the existing split-aware, refund-netting pivot engine with internal daily buckets and root category colors. Day details display net category totals and lazily fetch up to 100 recorded purchases separately. Gross ledger entries can differ from net report totals.

Each day has a dominant-color tint and proportional segmented strip. Funding categories are not additive income. Requests are limited to a month; a padded bank transaction query captures cross-month transfer legs. No provider requests, full investment analytics or Sheets history reads. Read-only; no migration or financial writes. Both components require rebuilding. Verify actual M1 rows and other destinations on the deployed dashboard before claiming coverage.
