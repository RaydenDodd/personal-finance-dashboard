# Dashboard financial calendars

Two optional, independently navigable main Dashboard widgets (existing layouts are unchanged):

- **Income & Contributions Calendar** uses recorded payroll statement take-home pay (green), native portfolio external net funding (blue), and accepted dated deposits/transfers into savings reporting accounts (yellow). The payroll source is not combined with bank income transactions, so linked paychecks are not counted twice. Native portfolio funding is not combined with Personal Finance investment ledger rows because they may describe the same transfer. Opening balances, adjustments, internal portfolio transfers, market gains and interest are not contributions. Savings-to-savings transfers do not count as new savings. The Personal Finance savings source remains owner-only; other users see that limitation. Unrecorded historical payroll and unmatched savings activity are not inferred. No projected paychecks are fabricated.
- **Spending Calendar** uses the existing split-aware, refund-netting pivot engine with internal daily buckets and root transaction-category colors. The new authenticated month-limited endpoint does not change the public pivot report's granularity options. Day details display exact signed category totals and lazily fetch up to 100 recorded purchases separately; gross ledger entries can differ from net report totals. The monthly report excludes planned rows, balance adjustments and transfers according to the existing stats rules.

Each day has a dominant-color tint and a proportional segmented strip; absolute magnitudes determine width, with equal segments if currencies differ. Funding days display category amounts rather than an additive total (a paycheck may fund savings/investments). Spending days display net spending in base currency. Exact currency values appear in day details; compact cell amounts are only presentation. Month navigation reads at most 31 days and never uses full investment analytics, historical market prices, or the net-worth dashboard calculation. Vue Query shares identical month requests and refreshes transaction-dependent queries with existing transaction invalidation.

Endpoints: GET /stats/calendar/spending and /stats/calendar/funding (from/to date-only, maximum 31 days), plus existing payroll and selected-day transaction list. No migration or financial writes. Backend and frontend builds are required. Verify owner/non-owner access, month boundaries, refunds, split expenses, linked paychecks, mixed days, savings transfers, mobile scrolling and dashboard persistence before marking live. Model unit tests cover leap months, proportional segments and category rollups.
