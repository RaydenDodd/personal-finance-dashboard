# Heatmap cold-start correction

The direct heatmap uses the same holdings selection as holdings and performers when no custom position period is needed. Today's daily period and unrealized/all views do not need a separate range replay. Custom historical ranges still require their own exact calculation; do not substitute another period's gains. Underlying heatmap mode must request exposure, not holdings alone. The scheduler checks every 15 seconds again and prioritizes pending base selections over pending dated selections. No persisted rows are invalidated by this change. Pending queries poll every five seconds. This does not yet remove the expensive replay for cold base/custom selections. Verify direct and underlying heatmaps, current daily, past daily, custom dates and portfolio grouping on the deployed UI.
